# Hackaton29.09.2027

Поскольку этап разработки решений на хакатоне жестко ограничен рамками с 15 по 29 сентября (14 дней), а предварительная экспертиза начнется сразу после, нам нужен 20-дневный спринт, который захватит несколько дней подготовки «до» и полировку «после» открытия ТЗ.
План разбит на 4 спринта по 5 дней. Работа ведется параллельно по двум трекам: Математическое ядро (Backend) и 3D-Интерфейс (Frontend).
------------------------------
## 📅 Спринт 1 (Дни 1–5): Подготовка и парсинг данных
Период предварительной подготовки (до и в первый день открытия ТЗ: ~12.09 – 16.09)

* День 1: Настройка окружения и архитектуры. Развертывание репозитория. Настройка связки FastAPI (Backend) и React/Three.js (Frontend).
* День 2: Написание ГИС-парсера. Написание Python-модуля на Geopandas для чтения геоданных (GeoJSON/OSM). Разделение карты на слои: здания, дороги, существующие теплосети.
* День 3: Базовая low-poly триангуляция. Реализация на бэкенде алгоритма Делоне (SciPy). Передача массива треугольников рельефа на фронтенд.
* День 4: Первое 3D-окно (Фронтенд). Отрисовка в Three.js low-poly ландшафта и «выдавливание» (extrusion) зданий по их этажности в 3D.
* День 5: Точка посадки. Реализация интерфейса добавления на 3D-карту «Нового перспективного здания» (Точка Б) и выбор существующей теплосети (Точка А).

## 📅 Спринт 2 (Дни 6–10): Математическое ядро и трассировка
Разгар хакатона: реализация главной фичи (~17.09 – 21.09)

* День 6: Построение графа ограничений. Превращение ГИС-карты в весовой граф (NetworkX). Автоматическое присвоение весов: здания = непроходимо, дороги = дорого, пустыри = дешево.
* День 7: Запуск алгоритма поиска пути. Интеграция алгоритма $A^*$ (A-Star). Первые тесты автоматической прокладки трубы от Точки А до Точки Б в обход low-poly зданий.
* День 8: Отрисовка трассы в 3D. Передача координат сгенерированной трубы на фронтенд и отображение её в виде яркой 3D-линии/трубопровода, лежащего на рельефе.
* День 9: Матрица штрафов за повороты. Модификация алгоритма $A^*$, чтобы он минимизировал углы поворота трубы (инженерное требование для теплосетей).
* День 10: Генерация 3-х вариантов. Настройка ядра на выдачу трех альтернативных путей: «Экономичный», «Кратчайший», «В обход дорог».

## 📅 Спринт 3 (Дни 11–15): Интерактивное редактирование и расчет сметы
Финальный рывок разработки: создание уникальной фичи (~22.09 – 26.09)

* День 11: Внедрение 3D Gizmo. Подключение TransformControls в Three.js. Возможность кликнуть на узел трубы и потянуть его мышкой в сторону.
* День 12: Реактивный пересчет (Reactive Pipeline). Настройка отправки измененных координат трубы обратно на бэкэнд для мгновенной валидации пути.
* День 13: Калькулятор сметы и гидравлики. Написание формул расчета стоимости (длина трубы × базовый тариф × коэффициенты препятствий) и примерных теплопотерь. Вывод данных на UI-панель.
* День 14: Контроль ошибок (Collision Detection). Реализация проверки: если пользователь затянул трубу под здание, включается красная подсветка и блокируется кнопка сохранения.
* День 15: Сборка MVP и заморозка кода (Code Freeze). Тестирование работоспособности всего конвейера: от загрузки файла до ручной правки трассы.

## 📅 Спринт 4 (Дни 16–20): Экспорт, упаковка и подготовка к питчу
Стабилизация и защита проекта (~27.09 – 01.10)

* День 16: Модуль экспорта в Blender. Реализация экспортера сцены в формат .gltf/.glb. Проверка в Blender: структура слоев должна сохраняться идеальной.
* День 17: Развертывание (Deployment). Деплой бэкенда на сервер (например, Docker/Vercel/Render) и фронтенда, чтобы жюри могло открыть сервис по прямой ссылке.
* День 18: Запись демо-видео (Screen-cast). Запись 2-минутного видео работы сервиса (загрузка -> генерация трассы -> ручное изменение -> экспорт в Blender). Это критически важно для прохождения предэкспертизы.
* День 19: Оформление Readme и репозитория. Создание красивого описания проекта на GitHub с инструкцией по запуску и описанием стек-технологий. Отправка решения на проверку (до 29.09).
* День 20: Подготовка презентации для финала. Разработка слайдов для питч-сессии на основе уникальности вашей идеи («Живая труба» и low-poly редактор). Отрепетированный прогон речи на 3 минуты.

# Реализация (Спринт 1, Дни 1–5)

# Hackaton29 — ГИС + 3D-визуализация теплосетей

Хакатон-проект: веб-приложение для посадки новых зданий на 3D-карту
и оценки их подключения к существующим теплосетям.

## Стек

| Сторона  | Технологии |
|----------|-----------|
| Backend  | Python 3.11+, FastAPI, GeoPandas, Shapely, SciPy (Delaunay), NumPy |
| Frontend | React 18, Three.js, Vite |

## Структура репозитория

```
├── backend/            # FastAPI-приложение
│   ├── requirements.txt
│   └── app/
│       ├── main.py             # точка входа (День 1)
│       ├── config.py           # настройки (День 1)
│       ├── deps.py             # DI-зависимости FastAPI (День 1)
│       ├── gis/
│       │   ├── parser.py       # ГИС-парсер на GeoPandas (День 2)
│       │   └── osm_loader.py   # загрузчик OSM-файлов (День 2)
│       ├── terrain/
│       │   └── triangulation.py# триангуляция Делоне (День 3)
│       ├── api/
│       │   ├── routes_map.py     # GET /api/map/layers (День 2)
│       │   ├── routes_terrain.py # GET /api/terrain/mesh (День 3)
│       │   └── routes_project.py # POST /api/project/connect (День 5)
│       └── data/               # геоданные (GeoJSON)
│           ├── buildings.geojson      # здания (OpenStreetMap)
│           ├── roads.geojson          # дороги (OpenStreetMap)
│           ├── heat_networks.geojson  # теплосети (OpenStreetMap)
│           └── fetch_osm.py      # загрузчик слоёв из OSM через Overpass API
├── frontend/           # React + Three.js
│   ├── package.json
│   ├── vite.config.js
│   ├── index.html
│   └── src/
│       ├── main.jsx            # вход React (День 1)
│       ├── App.jsx             # состояние приложения (Дни 1, 5)
│       ├── styles.css
│       ├── api/client.js       # HTTP-клиент к FastAPI (День 1)
│       ├── scene/
│       │   ├── MapScene.jsx    # 3D-сцена Three.js (Дни 4-5)
│       │   ├── terrain.js      # low-poly рельеф из меша (День 4)
│       │   ├── buildings.js    # extrusion зданий (День 4)
│       │   └── networks.js     # дороги и теплосети (Дни 4-5)
│       └── components/
│           └── Toolbar.jsx     # панель «Точка посадки» (День 5)
└── docs/               # подробные пояснения по дням и файлам
    ├── day1-architecture.md
    ├── day2-gis-parser.md
    ├── day3-triangulation.md
    ├── day4-3d-scene.md
    └── day5-landing-point.md
```

Подробное описание каждого файла — в `docs/` (по одному .md на день,
внутри — разбор всех файлов, созданных в этот день).

## Запуск

### Backend

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

API-документация (Swagger): http://localhost:8000/docs

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Приложение: http://localhost:5173 (запросы `/api/*` проксируются на порт 8000).

## Данные

Сервис работает на **реальных геоданных OpenStreetMap**: район
Западное Дегунино (Москва, САО) — 201 здание, 155 дорог и реальная
теплотрасса (`man_made=pipeline`, `substance=heat`), идущая от
котельной вдоль Бусиновского проезда и Ижорской улицы.

Загрузить слои для любого другого участка (bbox в градусах WGS84):

```bash
cd backend
python -m app.data.fetch_osm 55.8826 37.4920 55.8943 37.5129
```

## Как пользоваться (День 5)

1. **«+ Здание (Точка Б)»** — выберите этажность и размер, кликните
   по рельефу: появится полупрозрачное зелёное здание.
2. **«⌁ Теплосеть (Точка А)»** — кликните по красной линии теплосети.
3. Бэкенд рассчитает ближайшую точку врезки, длину подключения
   и ориентировочную тепловую нагрузку; пунктирная жёлтая линия
   покажет трассировку на 3D-сцене.
