# Сервис моделирования трасс подключения к тепловым сетям

Кейс ДИТ, хакатон ЛЦТ-2026. Сервис принимает конкурсный GeoJSON
(источник тепла, существующая сеть, камеры, точки подключения ОКС,
ограничения), строит **три варианта** схемы подключения, считает смету
по тарифам техприложения и ранжирует варианты по показателю
`S = 0,7·C/25 млн + 0,3·L/100` (меньше — лучше). Результат — GeoJSON
строго по контракту §7: `heat_network`, `heat_chamber`,
`technical_node`, `variant_summary`.

## Быстрый старт

```bash
docker compose up --build -d     # app (Java 11 + движок) + db (PostgreSQL 16)
# API и UI:  http://localhost:8080/
# Swagger:   http://localhost:8080/swagger-ui.html
```

```bash
curl -F "file=@dataset.geojson" http://localhost:8080/api/jobs   # → {"id": ...}
curl http://localhost:8080/api/jobs/{id}                          # статус: QUEUED/RUNNING/DONE/FAILED
curl http://localhost:8080/api/jobs/{id}/result -o result.geojson # готовый GeoJSON §7
```

Веб-интерфейс: загрузка файла, карта района, три вкладки вариантов,
калькуляция стоимости (участки + камеры + врезки + штрафы), таблица
сегментов с ДУ и ставками.

| Контейнер | Стек | Роль |

## Что реализует движок (актуальная редакция ТЗ + разъяснения)

- **§2.1** топология: лес деревьев без колец; камера ≤ 4 примыканий
  (сквозная на существующей линии = 2); повороты до 90° без удорожания;
- **§2.2** свой полигон ОКС: один финальный прямой участок от границы
  полигона к точке, отступ к своему полигону не применяется;
- **§2.3** гидравлика: ДУ — минимальный по расходу И предельной длине
  каждого непрерывного пути (многошаговый подъём, разъяснение №1);
  монотонность ДУ от точки к месту присоединения;
- **§2.4** присоединение: камера ≤ 10 м со свободными примыканиями,
  иначе новая камера на существующем участке; реконструкция отменена
  (разъяснение №14); отказ по рентабельности запрещён (№15);
- **§3.1/табл. 2** ограничения: отступы от чужих ОКС 5/7/9 м по ДУ
  (между гранями расчётных габаритов), водные/ж/д/social_area/
  prohibited_site — 1,0 м непроходимо; спецпроходы road ×1,60,
  tram ×1,75, gas ×1,25, power_cable ×1,15, пересечение существующей
  теплосети без врезки ×1,05; место врезки пересечением не считается (№10);
- **§3.2** камеры: стоимость по наибольшему ДУ всех примыкающих
  (включая существующие): ≤200 → 3 млн ₽, ≤500 → 5, ≤1000 → 8,
  ≤1400 → 12; врезка в существующую камеру — 5 млн ₽ за каждый новый
  участок; технические узлы стоимости не имеют;
- **§5** (опционально, `ENGINE_DEPTH_MODE=1`): вертикальный профиль
  (база 3,0 м, min 0,7 м, уклон ≤ 0,10, Kгл = 1 + 0,10·(h−3));
  в базовом 2D-режиме Kгл = 1, depth_start/depth_end = null;
- **§6** стоимость варианта = участки + новые камеры + врезки +
  штрафы (100 млн ₽ + 500 тыс. ₽·т/ч за неподключённую точку);
  S = 0,7·C/25 млн + 0,3·L/100;
- **§7** выход: 4 типа объектов, сохранение типов исходных id
  (числовые id точек и существующих камер остаются числовыми в
  start_node_id/end_node_id), концы LineString совпадают с узлами.

### Точность отступов на растре 3 м (коммит 9070570)

Сетка маршрутизации 3 м задана ТЗ; чтобы дискретизация не «съедала»
отступы, дополнительно:

- запретные зоны и буферы отступов блокируют ячейки по **пересечению**
  ячейки (свободная ячейка целиком вне зоны/буфера);
- диагональные ходы A* не режут угол заблокированной ячейки;
- допуск упрощения трассы — 0,4 м (`simplify_tolerance_m`);
- каждый оформленный участок проверяется по **точной геометрии** буферов;
  при заходе — откат и перероут с запасом 0/+1/+2/+`clearance_retry_max_m` м;
- новые камеры ставятся только в позиции, выдерживающие отступы
  (врезка сдвигается вдоль участка ±30 м; камера разветвления — в
  ближайшую чистую ячейку); существующие камеры не сдвигаются;
- совпадающие камеры врезки на одном участке сливаются (лимит
  примыканий §2.1 сохраняется);
- финальный проход контролирует отступы по итоговым геометриям и ДУ —
  нарушения попадают в предупреждения варианта (лог `app`).

```
│       │   └── job/              # задания, статусы, выдача результата
│       └── resources/
│           ├── reference.yaml    # ВСЕ тарифы/правила ТЗ (правится только он)
│           └── static/           # собранный фронтенд
├── frontend/             # React + Vite (dist собран заранее, см. ниже)
├── db/                   # init.sql — PostgreSQL 16
├── oracle/               # Python-оракул и контрактные тесты (в поставку НЕ входит)
│   └── tests/data/           # control/sample/official наборы + свежие e2e-результаты
├── scripts/              # fix_arp.sh — обход ARP-особенности VPS
├── docs/                 # Документация.md, Дельта_техприложения.md, Демо-сценарий.md
└── docker-compose.yml    # каноничный запуск: db + app
```

## Эксплуатационные заметки (боевой VPS)

- **DNS в контейнерах:** при systemd-resolved на хосте задать
  `dns:` в `/etc/docker/daemon.json` (иначе Maven не резолвит Central).
- **Maven-кэш:** `app/Dockerfile` монтирует buildkit-кэш
  `/root/.m2/repository` — повторные сборки быстрые и не ходят в сеть.
- **Фронтенд:** npm на сервере нестабилен, поэтому `frontend/dist`
  собирается заранее и коммитится; Dockerfile берёт готовый dist.
- **ARP:** после `docker compose up -d` при «висящем» порту 8080 —
  `bash scripts/fix_arp.sh` (статические neigh-записи для контейнеров).
