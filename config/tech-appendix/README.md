# Конфиги техприложения (кейс ДИТ «ЛЦТ-2026»)

Сюда вынесено **всё**, что техприложение задаёт числами и правилами, —
в коде эти значения не дублируются (требование §2.14 «Универсальность»
и защита от обновлений техприложения). Обновился документ → правим YAML,
прогоняем `validate_config.py` и golden-тесты, код не трогаем.

| Файл | Раздел техприложения | Содержимое |
|---|---|---|
| `diameters.yaml` | Табл. 4.1 + 4.2 | ДУ, пропускная способность, предельная длина, цены нов. строительства/реконструкции, расчётные габариты пары труб |
| `constraints.yaml` | Табл. 5.1 | Правила ограничений: запрет/спецпроход, мин. расстояния, углы, границы спецучастка, Kспец |
| `cost.yaml` | §8–9 | Шкала камер, цена врезки, штраф за неподключённый ОКС, веса и базы ранжирования |
| `depth.yaml` | §6 + 4.3 | Глубины, уклон 0.10, Kгл, параметры существующих коммуникаций (доп. задача) |
| `input_schema.yaml` | §2 | Контракт входного GeoJSON: типы, обязательные атрибуты, EPSG:4326→32637 |
| `output_schema.yaml` | §10 | Контракт выходного GeoJSON: 7 типов объектов, состав полей, geometry=null у сводной |
| `validate_config.py` | — | Fail-fast проверка конфигов при старте geo-engine |
