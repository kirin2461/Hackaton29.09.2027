# День 5 — Точка посадки

## Цель дня

Интерфейс добавления на 3D-карту **«Нового перспективного здания» (Точка Б)**
и выбора **существующей теплосети (Точка А)** + расчёт врезки на бэкенде.

## Сценарий работы

```
1. Кнопка «+ Здание (Точка Б)» → слайдеры этажности и размера →
   клик по рельефу → на карте появляется полупрозрачное здание.
2. Кнопка «⌁ Теплосеть (Точка А)» → клик по красной линии →
   линия подсвечивается жёлтым.
3. Если выбраны обе точки — фронтенд шлёт POST /api/project/connect,
   бэкенд считает врезку, на сцене рисуется пунктирная линия,
   в панели — длина подключения и тепловая нагрузка.
```

## Файлы дня

### `frontend/src/components/Toolbar.jsx`
Левая панель. Три режима (`view` / `addBuilding` / `selectNetwork`),
слайдеры этажности (1–25) и стороны здания (15–80 м), список теплосетей,
блок результата расчёта, кнопка сброса. Компонент «глупый»: всё
состояние приходит пропсами из `App.jsx`.

### `frontend/src/App.jsx` (логика Дня 5)
- `handleTerrainClick([x, y])` — строит квадратный контур здания
  вокруг точки клика (кольцо из 5 точек, замкнутое), сохраняет
  Точку Б в состояние.
- `handleNetworkClick(id)` — сохраняет Точку А; если Точка Б уже
  есть, вызывает `postConnect()` и кладёт ответ в состояние.
- `handleReset()` — полный сброс проекта.

### `frontend/src/scene/MapScene.jsx` (клики Дня 5)
Обработчик `click` на canvas переводит экранные координаты мыши в
нормализованные `[-1..1]`, создаёт `THREE.Raycaster` и дальше —
в зависимости от режима:
- `addBuilding`: ищет пересечение луча с мешем рельефа, конвертирует
  точку из координат сцены обратно в координаты карты
  (`x → x`, `z → -y`, инверсия `mapToScene`);
- `selectNetwork`: ищет пересечение с невидимыми «трубами» теплосетей
  (см. `networks.js`, День 4) и отдаёт наружу `id` линии.

### `backend/app/api/routes_project.py`
Роут `POST /api/project/connect`.

- **Вход (Pydantic):** `NewBuilding` — контур полигона, этажность,
  имя; `ConnectionRequest` — здание + `network_id` выбранной сети.
  Валидация: минимум 3 точки контура, 1–100 этажей.
- **Поиск сети:** линия ищется по id в слое теплосетей; нет — 404.
  Координаты сети приводятся к нормализованной системе карты
  (тот же сдвиг, что в `GISParser.to_response`).
- **Геометрия врезки:** `shapely.ops.nearest_points(здание, линия)`
  находит ближайшую пару точек между контуром и сетью; длина —
  расстояние между ними по прямой.
- **Тепловая нагрузка:** грубая оценка `площадь × этажность × 60 Вт/м²`
  (усреднённый показатель для жилых зданий, только для демо).
- **Ответ:** площадь и нагрузка здания, точки врезки `from_point` →
  `to_point`, длина подключения. Фронтенд рисует отрезок пунктиром
  (`buildConnectionLine`, `LineDashedMaterial`).

## Проверка дня

```
POST /api/project/connect
  {"building": {"polygon": [[500,560],[540,560],[540,600],[500,600]],
                "floors": 9, "name": "ЖК Тест"},
   "network_id": "h2"}
→ {"connection": {"length_m": 60.0, ...}, "building": {"heat_load_kw": 864.0, ...}}

POST с несуществующим network_id → 404 "Теплосеть не найдена"
```
