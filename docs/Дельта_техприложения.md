## По находкам

### 1. Ограничения: два вида правил вместо четырёх — ✅ ВНЕДРЕНО
**Сейчас:** `grid.py` обрабатывает 4 вида (`forbidden`, `min_distance`,
`crossing`, `special_passage`), `postprocess.py` проверяет углы пересечений
(`crossing_min_angle_deg` в reference.yaml).
**Меняется:** ветка `crossing` удаляется из растеризации и постпроцесса;
«запрет с мин. расстоянием» — единая ветка (запретная геометрия + буфер);
«спецпроход с Kспец» — вторая ветка. Из reference.yaml уходит
`crossing_min_angle_deg`. Тестовый набор пересобрать без Z3-crossing.
**Риск:** низкий — код удаляется, а не пишется.

### 2. CRS: вход EPSG:4326, расчёты EPSG:32637 — ✅ ВНЕДРЕНО
**Сейчас:** `loader.py` выбирает UTM-зону автоматически по медианной долготе
(`_choose_work_crs`), есть переопределение `ENGINE_WORK_CRS`.
**Меняется:** дефолт жёстко фиксируется на EPSG:32637 (без авто-зоны), вход
валидируется на EPSG:4326 (иначе — ошибка 400 с понятным сообщением).
Оценка «полдня» из находок — с запасом: механика pyproj уже на месте.

### 3. Дистанция до существующих ОКС по диаметру (5/7/9 м) — ✅ ВНЕДРЕНО
**Сейчас:** такого правила нет вообще — в модели только перспективные ОКС,
существующие здания не загружаются и не буферятся.
**Меняется:**
- `model.py`/`loader.py`: чтение существующих ОКС из входного набора;
- `grid.py`: динамические буферные зоны, зависящие от Ду трассы (5/7/9 м —
  в reference.yaml);
- `pipeline.py`: цикл «подбор Ду → проверка отступов → при конфликте
  пересмотр (смещение трассы/итерация)». Порядок в конвейере меняется:
  проверка дистанций — ПОСЛЕ гидравлики, а не до маршрутизации.
**Риск:** средний — самая объёмная из находок, нужна аккуратная итерация,
чтобы не зациклить «диаметр ↔ отступ».

### 4. Врезка: ≤10 м и ≤4 примыкающих, иначе новая камера — ✅ ВНЕДРЕНО
**Сейчас:** `tapping.py` — эвристика: поиск кандидатов в радиусе 1500 м,
ранжирование по стоимости «подводка + врезка».
**Меняется:** прямая реализация §8.2 — если камера в ≤10 м и у неё < 4
примыкающих участков → врезка в неё; иначе новая камера на ближайшей
проекции. Эвристика выбора уходит.
**Побочный эффект (важно):** стратегия варианта V3 «альтернативные врезки»
теряет смысл — при детерминированном правиле врезки одинаковы во всех
вариантах. Различие вариантов переносится в коридоры трассировки:
например V1 совместный/кратчайший, V2 раздельный, V3 совместный с объездом
(повышенный штраф за повороты/другой коридор). Сигнатурная дедупликация
уже есть — она отсечёт выродившиеся дубликаты.

### 5. Штраф за неподключённый ОКС ≥ 100 млн ₽ — ✅ ВНЕДРЕНО (100 млн ₽)
**Сейчас:** `unconnected_penalty: 50000000` в reference.yaml.
**Меняется:** значение ≥ 100 млн (по таблице техприложения). Семантика в
документации уже правильная: unconnected — аварийный режим, не инструмент
оптимизации; при таком штрафе «подключить всё» всегда дешевле — это
соответствует текущему поведению ранжирования.

### 6. Реконструкция: часть участка от врезки к источнику — ✅ ВНЕДРЕНО
**Сейчас:** `reconstruction.py` помечает ВЕСЬ перегруженный участок,
экспортер отдаёт его исходную геометрию целиком; множители Kспец/Kгл
к реконструкции не применяются (это уже соответствует).
**Меняется:**
- в `compute_reconstruction` считать подлинию от точки врезки до конца
  участка со стороны источника (`LineString.project/interpolate`);
- длина и стоимость — по подлинии, а не по всему участку;
- `exporter.py`: `reconstruction_segment` выводить с РЕАЛЬНОЙ геометрией
  подлинии, отдельной линией (не ссылкой на исходный объект).
**Риск:** низко-средний — геометрия подлиний уже используется в
`enforce_max_length`, приёмы те же.

### 7. Строгий выходной контракт — ✅ ВНЕДРЕНО
**Сейчас:** `exporter.py` отдаёт FeatureCollection с нашим `metadata` и
свободным набором properties; 7 object_type совпадают по духу
(new_segment, new_chamber, technical_node, tapping, reconstruction_segment,
reconstruction_chamber, unconnected), но имена полей и структура — наши.
**Меняется:**
- exporter переписывается под схему техприложения: ровно 7 типов объектов;
- сводка вариантов — фичей `variant_summary` с `geometry: null`
  (metadata-объект верхнего уровня уходит);
- белый список полей на каждый тип: ничего лишнего, даже с null;
- новый `tests/contract_test.py`: валидация выхода по схеме (типы, поля,
  отсутствие чужих ключей) — гоняется в смоуке.
**Риск:** средний — нужна сама схема (имена полей, рус/eng, единицы).
Как только будет файл схемы — перенос механический.

## Что НЕ меняется
- Sidecar-архитектура, Java-обёртка, стриминг 3 ГБ — техприложение их не касается.
- Вариантность 3 шт. и рейтинг 70/30 — подтверждены, меняется только источник
  различий (см. п.4).
- Задание на глубину: Kгл упомянут в находке 6 («к реконструкции не
  применяется») — значит, сам модуль глубины подтверждён техприложением,
  наша реализация в правильном направлении.
