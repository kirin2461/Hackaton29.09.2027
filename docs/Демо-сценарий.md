      (на чистой машине проверяющих — `docker-compose up --build`);

## По пунктам §4

1. **Соответствие стеку.** Показать Swagger UI (`springdoc-openapi-ui 1.7.0`,
   Java 11 / Spring Boot 2.6.3): «внешний интерфейс — Java-приложение,
   публичная точка входа одна — порт 8080». Вслух: PostgreSQL 16,
   docker-compose 1.29.2, всё поднимается одной командой `docker-compose up`.

2. **Загрузка входного набора.** На странице `/dit` перетащить официальный
   GeoJSON в зону загрузки. Вслух: до 3 ГБ, multipart-стриминг — файл
   пишется на диск, память не расходуется; схема входа — §1 техприложения
   (5 типов объектов + ограничения).

3. **Постановка задания.** Показать ответ `202` и `id` задания; статус
   обновляется автоматически (`QUEUED → PROCESSING → DONE`). На официальном
   датасете расчёт занимает ~15–30 с.

4. **Расчёт вариантов.** После `DONE` — вкладки вариантов: «построено три
   содержательно разных варианта: совместное подключение (базовый коридор),
   раздельное, совместное с альтернативным коридором; присоединение — строго
   по §2.4: камера ≤10 м от проекции со свободными примыканиями (< 4
   геометрически) — врезка в неё, иначе новая камера на участке».

5. **Рейтинг.** Показатель `S = 0,7·C/25 млн + 0,3·L/100` (меньше — лучше),
   рекомендуемый вариант подсвечен. На официальном датасете: все 17 точек
   ОКС подключены, лучший вариант ~533 млн ₽ / ~4,5 км новой сети.

6. **Карта.** Трассы рекомендуемого варианта: стволы и ветви, новые камеры,
   технические узлы на границах спецпроходов, спецпроходы — цвета в легенде.
   Показать: обход ж/д и водных объектов (запреты), финальный прямой подход
   к точке внутри её полигона ОКС (§2.2).

7. **Смета.** Таблица стоимости варианта: новые участки, новые камеры
   (шкала 3/5/8/12 млн ₽ по наибольшему примыкающему ДУ), врезки в
   существующие камеры (5 млн ₽ за каждый новый участок), штрафы за
   неподключённые точки (100 млн ₽ + 0,5 млн ₽ × расход). «Все ставки —
   из таблиц 1–2 техприложения, лежат во внешнем конфиге reference.yaml,
   код не трогаем».

8. **Инженерные правила.** На примере набора: подбор ДУ по расходу И
   предельной длине непрерывного пути (многошаговый подъём), монотонность
   ДУ к месту присоединения, спецпроходы через дороги/коммуникации с
   множителями таблицы 2, пересечение существующей теплосети ×1,05,
   отступы от чужих полигонов ОКС 5/7/9 м по ДУ.

9. **Неподключённые точки.** Если в наборе есть недостижимая точка —
   показать карточку «Неподключённые ОКС»: точка не отбрасывается молча,
   штраф честно включён в стоимость варианта (§2.5 — отказ по
   рентабельности запрещён).

10. **Скачивание результата.** Кнопка «Скачать выходной GeoJSON (§7)» —
    открыть файл: четыре типа объектов, `variant_id` у каждого,
    сводка `variant_summary` с `geometry: null`, концы участков совпадают
    с координатами узлов, id точек — числовые, как во входе.

11. **Доп. задача — глубина (§5).** Показать на контрольном/синтетическом
    наборе с `ENGINE_DEPTH_MODE=1`: у участков появляются `depth_start`/
    `depth_end`, на пересечении с кабелем — заглубление/подъём пандусом
    ≤ 0,10 с Kгл, технические узлы на пересечении отметки 3,0 м.

12. **Контрольный пример §7.3 (финал).** Прогнать
    `oracle/tests/data/control_example.geojson` через UI: результат
    `calculated_cost` = 13 974 800 ₽, `new_network_length` = 100,0 м,
    `score` = 0,6913 — «совпадает с эталоном техприложения до рубля».
