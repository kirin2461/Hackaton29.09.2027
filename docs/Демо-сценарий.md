**Время: ~7 минут.** Живой стенд: `http://82.114.226.204:8080/dit`
(резерв: Swagger UI `http://82.114.226.204:8080/swagger-ui.html` + curl).

Подготовка перед выступлением:
- [ ] стек поднят: `docker compose -f docker-compose.hostnet.yml up -d`
      (на чистой машине проверяющих — `docker-compose up --build`);
- [ ] файл конкурсного набора лежит локально, вкладка `/dit` открыта;
- [ ] Swagger UI открыт во второй вкладке (показать формальное §3 ТЗ).

## По пунктам §4

1. **Соответствие стеку.** Показать Swagger UI (`springdoc-openapi-ui 1.7.0`,
   Java 11 / Spring Boot 2.6.3): «внешний интерфейс — Java-приложение,
   публичная точка входа одна — порт 8080». Вслух: PostgreSQL 16,
   docker-compose 1.29.2, всё поднимается одной командой `docker-compose up`.

2. **Загрузка входного набора.** На странице `/dit` перетащить GeoJSON
   конкурсного набора в зону загрузки. Вслух: до 3 ГБ, multipart-стриминг —
   файл пишется на диск, память не расходуется.

3. **Постановка задания.** Показать ответ `202` и `id` задания; статус
   обновляется автоматически (`QUEUED → PROCESSING → DONE`).

4. **Расчёт вариантов.** После `DONE` — вкладки вариантов: «построено три
   содержательно разных варианта: совместное подключение (базовый коридор),
   раздельное, совместное с альтернативным коридором; врезки — строго
   по §8.2 (≤10 м и <4 примыканий — в камеру, иначе новая)».

5. **Рейтинг.** Таблица вариантов: показатель `0,3·стоимость + 0,7·длина`,
   рекомендуемый вариант подсвечен. Прокомментировать, почему он выиграл
   (короче строительство при сопоставимой цене).

6. **Карта.** На карте показать трассы рекомендуемого варианта: стволы и
   ветви, камеры, точки врезки, участки реконструкции существующей сети,
   спецпроход — цвета в легенде.

7. **Смета.** Таблица стоимости: прокладка по диаметрам, камеры, врезки,
   техузлы, реконструкция — «все ставки из справочника техприложения,
   лежат во внешнем конфиге, код не трогаем».

8. **Инженерные правила.** На примере набора показать: подбор диаметров по
   расходу, предельные длины с техузлами, реконструкцию перегруженных
   участков по цепочке к источнику, обход запретных зон, спецпроход.

9. **Задание на глубину (доп.).** Скачать результат, показать третью
   координату Z: «отметки глубины с шагом 0,5 м, пандусы с ограничением
   уклона, глубокая прокладка — с повышающим коэффициентом в смете».

10. **Частичный результат и выгрузка.** Если в наборе есть ОКС без маршрута —
    показать объект `unconnected` с причиной и штраф в смете: «расчёт не
    падает, честно показывает проблему». Выгрузить итоговый GeoJSON
    (до 500 МБ, стриминг) — финальный артефакт конкурса.

## Репетиция на дополнительном наборе (§2.14)

Перед защитой прогнать `oracle/tests/data/contest_sample_extra.geojson`

## Запасные ответы

- *«Почему Python внутри?»* — единственная публичная точка — Java; расчётное
  ядро (GeoPandas/Shapely/SciPy) работает как внутренний сервис в том же
  compose, §3 ТЗ выполнено формально.
- *«3 ГБ не влезет в память?»* — стриминг на всех ступенях: multipart на
  диск, ijson-парсинг батчами, отдача результата InputStreamResource.
- *«Откуда тарифы?»* — плейсхолдеры в `reference.yaml` до выдачи
  техприложения; заменяются конфигом.
